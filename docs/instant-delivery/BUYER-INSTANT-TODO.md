## Buyer TypeScript / Svelte migration

Active buyer code lives in `src/buyer`, with independent generated IIFEs in `assets/buyer/dist`. Entries are `state`, `classic`, `pin`, `blocks`, `account-shipping`, and `tracking`. WordPress dependency handles and localization remain authoritative; historical checkout handles are dependency aliases, not duplicate implementations. Canonical CSS and the 21 courier PNGs live under `assets/buyer/css` and `assets/buyer/img/couriers`. The old `assets/wp` assets and inactive handwritten state/map/Blocks/Choices/pin/account-shipping/tracking implementations have been removed.

- Classic uses real bits-ui combobox components over the original native Subdistrict/Province/courier selects. Native field names, selected values, required/disabled/ARIA and Woo country/state replacement remain intact; only explicit user selection emits a change. Lookup is read-only, bounded, cancellable and protected against stale responses. Country SelectWoo remains Woo-owned. Control geometry, logo frames, pricing and native-radio fallback are preserved.
- The Classic delivery pin is a focused Svelte component with typed queue/destination state and a small native Woo/jQuery bridge. Server pin saves require explicit `pin_saved:true`; mutation requests are serialized rather than aborted.
- Blocks retains Woo-provided React registrations, store actions, native shipping-rate inputs and address-edit ownership. Svelte owns focused map information/pin-status children inside React-owned hosts. Blocks district controls remain native Woo-compatible selects; this boundary is intentional.
- Account shipping uses an independent Svelte entry importing shared typed Leaflet helpers, with no Blocks/React/store dependency. Svelte owns the pin/status presentation; the original account form, six native address fields, nonce, validation and Save address submission remain Woo-owned. Pending district identities are confirmed through read-only lookup, not invented or persisted early.
- Tracking uses focused Svelte details/history components in the existing shortcode containers, typed read-only transport/controller state and a native event bridge. Existing classes, query-string lookup and `window.trackOrder` compatibility remain; superseded lookups cannot replace newer results.
- `map/config.ts`, `map/types.ts` and `map/leaflet.ts` isolate provider configuration. Bundled Leaflet is the only implementation; unknown providers fail without library fetches. Google Maps/BYOK is a future boundary, not implemented here.

**Remaining migration work:** `assets/buyer/js` still contains native cart/Classic district, shipping/payment/order-review and account-billing/form compatibility bridges. In particular, `checkout/blocks-compatibility.js` and `shipping-payment.js` retain substantial legacy fallback behavior; further extraction/reduction requires preserving cart/theme coverage, not deleting supported fallbacks blindly. The shared legacy bootstrap and older billing/shipping templates also remain. Four Woo-version-dependent Blocks React adapters remain transitional `@ts-nocheck` modules; their shared state/address/map modules and Svelte children are typed, but full native-store/hook contracts still require explicit typing. Source lint covers the typed buyer tree and previously linted native order-review/editor boundaries; this migration does not claim the untouched legacy fallback tree is warning-free.

Verification uses production TS/Svelte runtime compilation and isolated Chromium fixtures, never live provider/order/payment calls. Native Happy DOM observer closures are retained within test fixtures to avoid their weak-reference lifetime artifact under Bun GC; actual asynchronous record delivery is preserved. The frontend gate builds buyer entries before testing generated-asset existence; packaging rebuilds all entries. Installed-theme/provider readiness and real payments remain the live release gates below.

### Blocks saved-address postal recovery

Saved-pin and verified-village readiness are independent. A failed/empty shipping-postcode lookup must not write an empty destination over the saved server state, and visible cached shipping rates are not permission to submit an unverified plugin address. The native address card shows one actionable lookup status/retry rather than duplicate missing-district and choose-pin notices. Opening Edit after completed empty/error retries once; explicit retry sends a nonce-protected `retry=1` to bypass the shared positive postal cache. Billing-checkbox changes do not choose a village or change lookup postcode.

Postal cache v4 ignores older polluted empty entries and stores only bounded nonempty usable options for five minutes. Successful zero matches are not cached, malformed responses remain failures, and failed explicit refresh does not corrupt a good cache. Lookup results reconcile current/restored IDs against every accepted option list and update canonical labels; an invalid preferred stored identity does not prevent trying other valid saved candidates. No village IDs or pin coordinates are invented. Eight real React/Chromium recovery scenarios exercise postcode 55581, saved pins, Edit/card Retry, empty/HTTP/malformed/invalid rows, billing busy updates, effect-owner transfers and stable courier review, using isolated production PHP lookup fixtures rather than live API calls. Actual provider results still require checking the new lookup response if no options return after deployment.

### Reviewed courier integrity across validation retries

Blocks native courier event ordering: document capture records the exact buyer choice without publishing extension data or notifying React until the native event finishes. Publishing during capture could reset the radio before Woo's root `onChange`, swallow its shipping-selection request, and launch an unwanted restoration. Queued restorations now recheck current native busy state, rate availability and intent generation, preserve native package-ID types, and resolve repeated package controls within the clicked list. Pointer/keyboard/reselect browser regressions use React's real native event boundary, not a document-capture mock shipping writer.

GoSend reload fee recovery: quote generation, cart-fee validation and final order validation derive package category from the same current physical products. A method-local nondefault category previously differed from the raw Woo package after reload, leaving selected GoSend visible but dropping its validated admin fee. Reconstructed-session/raw-package regressions verify one native fee and strict final order totals without extra pricing requests. Explicit quote refresh also invalidates both cart package keys and initialized shipping package keys, so a fresh request with an empty `WC_Shipping` object cannot retain old cached rate tokens while clearing the quote cache. No fee is invented from stale rate metadata, and native chosen shipping IDs remain unchanged. Isolated browser reload tests display amounts generated by the production PHP quote/controller fixtures; installed Woo/provider verification remains a separate live gate.

Matching-courier warning correction: native customer/rate busy state is not a courier identity mismatch. When reviewed and selected package/rate IDs match, the changed-courier validation is cleared even while an update is pending; a separate `kiriof-shipping-selection-pending` validation with localized Updating shipping options text blocks submission until settling. Only real mismatches display the review/reselect message. An existing explicit review still reconciles during saved-pin initialization, and scoped clears never remove Terms & Conditions or other native validation. Real React and Chromium regressions verify matching GoSend during billing/rate activity, pending-submit prevention, idle clearing and unchanged final identity protections.

A versioned package/rate-ID review is stored separately from current Woo shipping defaults and posted as Checkout extension `shipping_selection` (Blocks) or native hidden `kiriof_shipping_selection` (Classic). Initial stable rates seed the review once; explicit native buyer choices update it. Terms validation failure, billing-address checkbox updates, temporary missing rates and price/label refreshes do not silently rewrite the reviewed courier.

Blocks restores an exact reviewed rate through the public native `wc/store/cart.selectShippingRate` action only after customer/rate updates settle and every reviewed ID is still available. Missing quotes—including COD-ineligible Instant—or a failed restoration stay blocked with a request to review/select again; no loop, fabricated rate, DOM polling or programmatic radio click is used. Capture-phase native input events record intent; duplicate rate IDs use their native package container context, not rate ID alone. Classic retains reviewed IDs through refreshed shipping fragments and blocks a mismatched submission until explicit reselection.

A read-only server guard runs at priority 5 before Express/Instant route validators on actual place-order requests. It compares the posted package/rate IDs with current available rates, native session selections and order shipping-line method/instance/courier/service identity. Switching into/away from plugin shipping, malformed review data, missing rates or changed lines rejects before plugin quote snapshot/transaction writes; ordinary Store API PATCH edits and unrelated third-party-only checkout remain unaffected. This is a courier identity guard—not prior-price approval; existing exact quote/fee/total validation still applies. Older open checkout pages without the new review payload must reload before ordering.

Real React/browser tests cover unchecked terms → GoSend → failed terms → retry, separate billing → GoSend → accepted terms → same-billing update, exact native restoration, missing rates/COD, failed restoration and explicit Cargo re-review. PHP regressions verify final rejection before route writes and stable package ordering. No live merchant order or booking was submitted.
